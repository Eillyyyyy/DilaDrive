# DilaDrive Project Cleanup Audit

This inventory records the decision before removal. Paths are relative to the workspace root. Git stores the project prefix as `DilaDrive/` and the Windows working directory displays it as `diladrive/`.

## Audit scope

- React entry, page selection and imports were traced from `web-admin/index.html`, `src/main.jsx` and `App.jsx`. Vite/Tailwind configuration, page commands, test imports and dynamic loading patterns were included.
- Flutter entry points, conditional HTTP clients, routes, package imports, platform resources, generated plugin registration, pubspec, Firebase configuration and tests were checked. The root entry wrapper can still be invoked explicitly.
- Spring controllers, advice, mapped interceptors, DTOs, services, repositories, resource profiles and JPA mappings were evaluated in the context of component scanning and framework binding. Absence of an import is insufficient for controllers, converters or configuration.
- SQL baseline, numbered migrations, manual scripts and disposable-schema test references were reviewed as schema history. Local runtime files, uploads, secrets and platform setup were excluded from deletion.
- Filename and path searches included scripts, tests, documentation, IDE launch files and the historical `structure.txt`. Git index, working-tree status and history were checked for candidates. The dependency trees and generated bundles were treated as artifacts at their directory boundary.
